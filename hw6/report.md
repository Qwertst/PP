Задача: продемонстрировать переупорядочивание доступа к памяти на схеме "флаг
готовности + данные". Производитель пишет `data`, затем взводит `ready`;
потребитель крутит `ready` и по факту читает `data`. Поставлены два эксперимента на двух архитектурах; проверены `bool`, `atomic<bool>` relaxed и release/acquire.

## 1. Пререквизиты

| | x86 | ARM |
|---|---|---|
| Процессор | Intel Xeon Gold 6230 @ 2.10 GHz | Apple M3 Pro |
| Ядра / потоки | 12 ядер (1 сокет, 1 поток/ядро) | 12 ядер (6P + 6E) |
| ОЗУ | 44 GiB | 36 GiB |
| ОС / ядро | Ubuntu 22.04.5 LTS, Linux 5.15.0-143-generic | macOS 15.7.1, Darwin 24.6.0 |
| Компилятор | g++ 11.4.0 | Apple clang 16.0.0 |
| libc | glibc 2.35 | libSystem (Darwin libc) |
| Модель памяти железа | x86-TSO | weak |

## 2. Что измеряем

**Эксп. 1 - `reorder.cpp`**
Перестановку поймали, если потребитель увидел `ready == true`, но прочитал
`data == 0` (счётчик `stale`). Виновата либо Store->Store у производителя (флаг уехал вперёд данных), либо Load->Load у потребителя (чтение `data` обогнало чтение `ready`). Второй счётчик `missed` - флаг так и не увиден (ловит зависание `bool`-варианта). Тип `data`/`ready` задаётся макросом `MODE`: `PLAIN` (`int`/`bool`), `RELAXED`, `ACQREL`.

**Эксп. 2 `storeload.cpp`**
При последовательной согласованности `r1 == 0 && r2 == 0` невозможно. Если
наблюдается - поймали Store->Load: запись осела в store buffer, а чтение другого адреса её обогнало.

## 3. Лайфхаки для замеров

- `data` и `ready` на разных кэш-линиях (`alignas(128)`). Иначе линия мигрирует между ядрами целиком и `ready==true` при `data==0` получить нечем
- Два вечных потока, синхронизация семафорами только с `main`. Единственный межпоточный канал внутри раунда - сама пара `(ready, data)`. Сброс `data=0; ready=false` между раундами race-free (семафоры дают happens-before).
- Предохранитель `SPIN_CAP` - чтобы `bool`-режим не зависал навсегда, а засчитывался как `missed`.
- `prepare_data()`. В `bool -O2` тормозит производителя, чтобы потребитель гарантированно дошёл до своей единственной (вынесенной компилятором из цикла) проверки первым. На ARM-прогоне наоборот `-DPREP_ITERS=0`: на десятках млн раундов задержка слишком дорога.
- Пиннинг на разные ядра через `pthread_setaffinity_np`, на macOS - заглушка, там хватило числа раундов и разнесённых кэш-линий.
- `random_delay` рассинхронизирует потоки. `atomic_thread_fence(seq_cst)` (-> `mfence`) убирает аномалию.

## 4. Результаты

**Эксп. 1** (`reorder.cpp`; x86 - 500 000 раундов, ARM - 50 000 000):

| режим | x86 | ARM | причина |
|---|---|---|---|
| `bool`, -O2 | зависает (`missed`) | зависает (`missed`) | перестановка **компилятора**: чтение `ready` вынесено из цикла |
| `atomic` relaxed | `stale` **0** | `stale` **32583** (~1 на 1535) | **железо**: x86-TSO запрещает Store->Store / Load->Load, ARM weak разрешает |
| `atomic` rel/acq | `stale` 0 | `stale` 0 | барьеры `stlr`/`ldar` запрещают перестановку везде |

На -O0 `bool` перечитывает флаг каждую итерацию и на x86 даёт `0/0` - но это
скорее везение.

**Эксп. 2** (`storeload.cpp`, x86, 10 000 000 раундов):

| вариант | `r1==0 && r2==0` | частота |
|---|---|---|
| без барьера | 7672 | ~1 на 1303 |
| `mfence` между store и load | 0 | - |

## 5. Объяснение

- x86 - это TSO. Единственная разрешённая перестановка - Store->Load (эксп. 2, ~1/1300). Схема "флаг+данные" уязвима к Store->Store / Load->Load, а их на x86 нет - поэтому эксп. 1 всегда `0`.
- ARM - weak: то же место ломается (эксп. 1, `stale = 32583`), потому что AArch64 разрешает все четыре перестановки.
- `bool` опасен из-за компилятора. При -O2 чтение флага инвариантно для однопоточного анализа и выносится из цикла -> программа зависает на обеих архитектурах.
- relaxed чинит компилятор, но не железо: запрещает кэшировать/выносить/склеивать обращения, но не аппаратные перестановки. На x86 этого хватает, на ARM - нет.
- release/acquire - единственный переносимо корректный вариант: на x86 бесплатно (обычный `mov`), на ARM ценой барьеров (`stlr`/`ldar`).

## 6. Воспроизведение

```bash
cd hw6
make

make run
./plain_O0 500000 # bool, -O0
./plain_O2 3 # bool, -O2
./relaxed 500000 # atomic relaxed
./acqrel 500000 # atomic release/acquire
./storeload 10000000 # Store->Load без барьера
./storeload_fence 10000000 # Store->Load с mfence

# Для арма
make run-arm ROUNDS=50000000 # relaxed + acqrel, -DPREP_ITERS=0, 50 млн раундов
```
