## 2. Алгоритм

`LockFreeSet<T>` - отсортированный односвязный список с двумя сентинелами `head_` (-inf) и `tail_` (+inf). От `T` нужен `operator<` и конструктор по умолчанию (сентинелы создаются как `new Node(T{})`, их ключи не читаются - `static_assert(is_default_constructible)`).

Удалить узел одним CAS нельзя: между "отвязать" и "никто не ссылается" возможна
гонка с соседней вставкой. Поэтому удаление двухфазное: сперва узел помечается удаленным, затем физически отвязывается.

### Лайфхаки

 - Mark-бит в младшем бите указателя. Поле `next` хранит указатель на
преемника и бит удаления в одном машинном слове. Узлы выровнены, поэтому младший бит свободен. Один CAS по `next` атомарно проверяет сразу - удален ли узел и изменился ли next.

 - Отвязанные узлы кладутся в lock-free стек `retired` удаляются только в деструкторе. Читать `next`/`key` уже отвязанного узла безопасно-> нет use-after-free, операции остаются lock-free. Плата - рост памяти пропорционально числу удалений за время жизни.

## 3. Проверка линеаризуемости

Параметры: `N in [3,6]`, типы `add/remove/contains/isEmpty`, операнды `{0,1,2}`, случайное начальное состояние, 2000 сценариев x 200 прогонов = 400 000 прогонов.

```
нарушений линеаризуемости: 0
средн. допустимых трейсов/сценарий: 2.987
средн. наблюдённых трейсов/сценарий: 2.3645 (>1 => перекрытие потоков)
```

0 нарушений на 400 000 прогонов. Среднее число различных наблюдённых трейсов ~ 2.36 - потоки действительно перекрываются, тест видит разные линеаризации.
